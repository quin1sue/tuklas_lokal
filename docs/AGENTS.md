# Documentation Agent Instructions

When editing project docs:
- Keep product scope, architecture, and implementation decisions aligned.
- Mark undecided choices as `Pending` or `Provisional`; never present them as approved.
- Update `DECISIONS.md` for decisions with architectural consequences.
- Keep MVP exclusions explicit.
- Prefer concrete acceptance criteria and testable statements.
- Do not claim external API costs/terms/model availability are current without verifying official sources.
- Update README links when adding or renaming documentation.
- Avoid duplicating large sections; link to the canonical document.
